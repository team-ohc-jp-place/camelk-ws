= REST API サービスの実装
:experimental:
:tip-caption: :bulb:
:imagesdir: images

== 1. 目的

Apache Camel は、REST DSLを用いて、get、post、deleteなどのメソッドを指定するRESTサービスを作成することができます。

このセクションでは、OpenAPIの定義を用いて、REST API の エンドポイントを、Camel で作成します。

image::restapi/restapi-000.png[pic, 800]

このシナリオでは、APIを使用して、ユーザーがファイルなどの汎用オブジェクトをバックエンドシステムに保存し、それに対するCRUD操作を許可します。

バックエンドは、オープンソースソフトウェアで Amazon S3 と API互換のオブジェクトストレージである、MinIO を使用していきます。

* **REST DSL**: link:https://camel.apache.org/manual/rest-dsl.html[https://camel.apache.org/manual/rest-dsl.html,window="_blank"]
* **OpenAPI**: link:https://www.openapis.org/[https://www.openapis.org/,window="_blank"]
* **MinIO**: link:https://min.io/[https://min.io/,window="_blank"]

---

== 2. OpenAPI定義を Camel にインポートする

ベースになる OpenAPIの定義は、`minio/openapi.yaml` に記述されています。
中身を見て確認をしてみてください。

このAPIを用いて実装したい操作は、以下の内容です。

* **get /v1**: 含まれているオブジェクトの名前の一覧表示
* **get /v1/{name}**: オブジェクトのコンテンツを取得する
* **put /v1/{name}**: 新しいオブジェクトの作成
* **delete /v1/{name}**: オブジェクトの削除

[source, bash]
----
---
openapi: 3.0.2
info:
  title: Camel K Object API
  version: 1.0.0
  description: A CRUD API for an object store
paths:
  /v1:
    get:
      responses:
        "200":
          content:
            application/json:
              schema:
                type: array
                items:
                  type: string
          description: Object list
      operationId: list
      summary: List the objects
  /v1/{name}:
    get:
      responses:
        "200":
          content:
            application/octet-stream:
              schema:
                type: string
          description: The object content
      operationId: get
      summary: Get the content of an object
    put:
      requestBody:
        description: The object content
        content:
            application/octet-stream:
              schema:
                type: string
        required: true
      responses:
        "200":
          content:
            application/json:
              schema:
                type: string
          description: The object has been created
      operationId: create
      summary: Save an object
    delete:
      responses:
        "204":
          description: Object has been deleted
      operationId: delete
      summary: Delete an object
    parameters:
    - name: name
      description: Name of the object
      schema:
        type: string
      in: path
      required: true
----

まずは、OpenAPIの定義をインポートして、REST API のエンドポイントと Camel の Route を生成します。ターミナルを開き、下記のコマンドを実行してください。

[source, bash]
----
camel plugin add generate
camel generate rest --input minio/openapi.yaml --routes --type=yaml --output api.yaml  
----

コマンドの実行完了後、`api.yaml` というファイルが作成されます。
まずはソースコードエディターを開いて内容を確認してください。

image::restapi/restapi-003.png[pic, 1200]

このコードは、Camel の `REST DSL` を使用して、REST APIを定義している部分です。
それぞれのHTTPメソッド（DELETE, GET, PUT）が具体的なエンドポイントとともに定義され、オブジェクトストレージのバケットに対する操作を行うために `direct:` Route にルーティングされています。
以下に詳細な解説をします。

`**get**` **メソッド(リスト取得)**

* エンドポイント: `/v1`
** このエンドポイントはオブジェクトストレージのバケット内のオブジェクト一覧を取得します。
** レスポンスの内容: `application/json` 形式でレスポンスを返します。
** ルーティング: リクエストは `direct:list` という内部ルートに送られ、オブジェクトストレージのバケット内のオブジェクトのリストを取得して返します。

`**get**` **メソッド(オブジェクト取得)**

* エンドポイント: `/v1/{name}`
** `name` というパスパラメータを受け取り、特定のオブジェクトを取得します。
** パラメータ `name` は必須で、オブジェクト名として使用されます。
** レスポンスの内容: 取得されたオブジェクトは `application/octet-stream` 形式で返されます（バイナリ形式）。
** ルーティング: リクエストは `direct:get` という内部ルートに送られ、オブジェクトストレージのバケットから指定されたオブジェクトを取得します。

`**delete**` **メソッド**

* エンドポイント: `/v1/{name}`
** `name` というパスパラメータを受け取り、オブジェクトストレージのバケット内のオブジェクト名として使用します。
** パラメータ `name` は必須で、データ型は `string` です。
** ルーティング: このエンドポイントに対するリクエストは、`direct:delete` という内部ルートに送られます。このルートは、指定されたオブジェクトをオブジェクトストレージのバケットから削除する役割を果たします。

`**put**` **メソッド(オブジェクト作成)**

* エンドポイント: `/v1/{name}`
** `name` というパスパラメータで新しいオブジェクトをアップロードします。
** パラメータ `name` は必須で、アップロードするオブジェクトの名前を指定します。
** `body` はアップロードされるオブジェクトの内容を示します。この内容はリクエストボディに含まれ、必須です。
** リクエストの内容: `application/octet-stream` 形式でデータを受け取ります。
** ルーティング: リクエストは `direct:create` という内部ルートに送られ、オブジェクトストレージのバケットにオブジェクトをアップロードします。

---

== 3. Route の処理を実装する

Camel の link:https://camel.apache.org/components/{{ CAMEL_VERSION }}/aws2-s3-component.html[AWS S3 Storage Service,window="_blank"] コンポーネントを使用して、Amazon S3 互換のオブジェクトストレージである、MinIO に対して操作をする処理を実装していきます。

=== 3.1 含まれているオブジェクトの名前の一覧表示

`direct` の `Endpoint Properties` の `Name` が `list` となっている `direct` のシンボルをクリックします。
右側のプロパティを確認し、`Description` にも、`direct:list` と入力をしてください。

image::restapi/restapi-005.png[pic, 1200]

続いて、`direct:list` シンボルの メニューをクリックし、`Add Step` を選択します。

image::restapi/restapi-006.png[pic, 400]

`Components` のタブから `AWS S3 Storage Service` を探して選択をしてください。
左上のテキストボックスに `S3` と入力をすると、絞り込みができます。

image::restapi/restapi-007.png[pic, 800]

これで、`direct:list` の後に、`aws2-s3` が追加されます。

`aws2-s3` のシンボルをクリックすると、右側にプロパティが表示されますので、
Parameters 項目に、以下の内容を設定してください。
他の項目は、デフォルトのままで構いません。

* **Bucket Name Or Arn**: {{ API_BUCKET }}
* **Oparation**: listObjects

MinIOへの接続の認証情報など、その他の必要な Parameters については、他の Route の処理でも共通で使用するため、`minio` フォルダの `minio.properties` ファイルに記述しておきます。

`minio/minio.properties` に、以下のコードを追加してください。

[source, bash]
----
# MinIO Bucket
api.bucket={{ USER_ID }}

# Minio information
minio.endpoint=https://minio-api-minio.{{ ROUTE_SUBDOMAIN }}
minio.access-key=minio
minio.secret-key=minio123

# Camel AWS2 S3
camel.component.aws2-s3.region=eu-west-1
camel.component.aws2-s3.access-key={{ S3_ACCESS_KEY }}
camel.component.aws2-s3.secret-key={{ S3_SECRET_KEY }}
camel.component.aws2-s3.uri-endpoint-override={{ S3_ENDPOINT }}
camel.component.aws2-s3.override-endpoint=true
camel.component.aws2-s3.autoCreateBucket=true
camel.component.aws2-s3.forcePathStyle=true
----

image::restapi/restapi-008.png[pic, 800]

次に、複数のオブジェクトが含まれていた時に、分割をするための `split` を追加します。
`aws2-s3` シンボルの メニューをクリックし、`Append` を選択します。

image::restapi/restapi-009.png[pic, 600]

`Type: Processor` の中から `split` を探して選択をしてください。
左上のテキストボックスに `split` と入力をすると、絞り込みができます。

image::restapi/restapi-010.png[pic, 800]

`split` のシンボルをクリックすると、右側にプロパティが表示されますので、
Parameters 項目に、以下の内容を設定してください。
他の項目は、デフォルトのままで構いません。

* **Expression**
** **Language**: simple
** **Expression**: ${body}
* **AggregationStrategy**: #class:org.apache.camel.processor.aggregate.GroupedBodyAggregationStrategy
* **Parallel Processing**: true
* **Streaming**: true
* **Aggregation Strategy Method Allow Null**: true

`AggregationStrategy`は、分割した各メッセージを集約時にどのように1つにマージするかを指定します。
`GroupedBodyAggregationStrategy` は、入力された メッセージの Body を、単一のメッセージの Body としてList型のオブジェクトに集約します。

image::restapi/restapi-011.png[pic, 1200]

image::restapi/restapi-012.png[pic, 800]

`Type: Processor` の中から `transform` を探して選択をしてください。
左上のテキストボックスに `transform` と入力をすると、絞り込みができます。

image::restapi/restapi-013.png[pic, 800]

== 4. REST API サービスの動作を確認する

作成した REST API サービスを、実行して確認してみます。

OpenShift DevSpaces のターミナルで、以下のコマンドを実行してください。

[source, bash]
----
camel run api.yaml --property file:minio/minio.properties
----

実行すると、以下のようなログと、右下にポップアップが表示されるので、`yes` を表示してください。

image::restapi/restapi-033.png[pic, 800]

左のエクスプローラの `ENDPOINTS` に、`user-port-forward (8080)` が表示されていますので、`Copy endpoint URL to clipboard` をクリックして、URLをクリップボードにコピーします。

別のターミナルを開き、以下のコマンドを実行します。

[source, bash]
----
URL=<コピーした endpoint URL>/v1
----

image::restapi/restapi-034.png[pic, 1200]

では、まず現在のオブジェクトの一覧を確認してみましょう。
ターミナルから、以下のコマンドを実行します。
