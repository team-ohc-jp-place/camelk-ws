== 1. Splitter EIP について

Apache Camelの link:https://camel.apache.org/components/{{ CAMEL_VERSION }}/eips/split-eip.html[Splitter EIP（Enterprise Integration Pattern）,window="_blank"] は、メッセージを複数の小さなメッセージに分割して、それぞれを個別に処理するためのパターンです。
Splitterは、大きなメッセージを扱う場合や、メッセージの一部ごとに異なる処理を行いたい場合に便利です。

image::split/Sequencer.gif[pic]

**Splitterの基本的な動作**

* 入力メッセージ: 1つの大きなメッセージを受け取ります（例: CSVファイル、XMLドキュメント、リスト）。
* 分割処理: メッセージを個別のエレメント（行、タグ、アイテムなど）に分割します。
* 個別処理: 各エレメントを個別のメッセージとして下流のルートで処理します。

== 2. メッセージ の分割

左のエクスプローラー上で、`labs/split-pattern.yaml` 右クリックをして、メニューから `Open with Kaoto Graphical Editor for Camel` を選択し、Kaoto のグラフィカルエディターを開きます。

以下のような Route が設定されています。

image::split/split-001.png[pic,600] 

内容については次の通りです。

image::split/split-002.png[pic,800] 

* `timer` コンポーネント: 指定した間隔でメッセージを生成します。
** `uri`: `timer:split-pattern` はタイマーの名前を指定しており、ユニークであれば任意の文字列でかまいません。
** `period`: 1000msごとにメッセージをトリガーします。
** `repeatCount`: このルートが実行される回数を指定します。`1`なので、一度だけ実行されます。
* `setBody`: メッセージのボディを手動で設定します。
** `simple`: Simple言語を使用してボディを設定します。この例では、CSV形式のテキストを設定しています。
* `unmarshal`: メッセージボディをCSVからJavaオブジェクトに変換します。
** `delimiter``: CSVの区切り文字をカンマ（,）として設定しています。
** `useMaps`: trueに設定すると、CSVの各行がJavaのMapオブジェクトに変換されます。CSVのヘッダー（id、name）がキーになり、各行の値が対応する値になります。
* `log`: `${body}` は、メッセージボディをログに出力します。

このサンプルソースを動かしてみます。
OpenShift DevSpaces のターミナルで、以下のコマンドを実行してください。

[source, bash]
----
camel run labs/split-pattern.yaml
----

`setBody`で設定したcsv形式のデータが、Javaオブジェクトに変換され、ログに表示されました。

image::split/split-003.png[pic,1200] 

ログの確認後、`Ctrl+C` もしくは、ターミナル右上のゴミ箱のアイコンをクリックして、終了してください。

---

それでは、Splitを使用して、メッセージを分割する処理を追加します。

Kaoto のグラフィカルエディター上で、`unmarshal` シンボルの メニューをクリックし、`Append` を選択します。

image::split/split-004.png[pic,800] 

`Type: Processor` の中から `split` を探して選択をしてください。
左上のテキストボックスに `split` と入力をすると、絞り込みができます。

image::split/split-005.png[pic,800]

`unmarshal` の後に、 `split` が配置されました。

`split` のシンボルをクリックして、`Expression` のエンピツのマークをクリックします。

image::split/split-006.png[pic,800]

`Simple` 言語を選択し、`Expression`欄に以下を入力してください。

* `Expression`: ${body}

image::split/split-007.png[pic,800]

---

それでは、メッセージが分割されることを確認してみましょう。
OpenShift DevSpaces のターミナルで、以下のコマンドを実行してください。

[source, bash]
----
camel run labs/split-pattern.yaml
----

先ほどのJavaオブジェクトのデータが、3つのメッセージに分割されてログに表示されました。

image::split/split-008.png[pic,1200] 

ログの確認後、`Ctrl+C` もしくは、ターミナル右上のゴミ箱のアイコンをクリックして、終了してください。

== 3. Parallel Processing

`Parallel Processing` を有効にすると、Camelはsplitで分割されたメッセージを複数のスレッドを使用して並行に処理します。これにより、処理時間が短縮され、スループットが向上します。

`Split` シンボルをクリックし、右側のプロパティから `Parallel Processing` を探してスイッチをオンにします。

image::split/split-009.png[pic,1200]

それでは、もう一度実行をします。
OpenShift DevSpaces のターミナルで、以下のコマンドを実行してください。

[source, bash]
----
camel run labs/split-pattern.yaml
----

ターミナルに以下のような ログ が表示されます。分割されたデータの ログ の表示が順不同になり、
赤枠で囲った部分を見ると、スレッドIDがそれぞれ異なっていることが確認できます。
（もし表示順が同じだった場合は、何度かやり直してみてください）

image::split/split-010.png[pic,1200]

ログの確認後、`Ctrl+C` もしくは、ターミナル右上のゴミ箱のアイコンをクリックして、終了してください。
