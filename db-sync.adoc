== 1. 目的

**Camel/Kafka/Debezium** を使用して、データベース間の同期を行う仕組みを構築します。

image::dbsync/dbsync-001.png[pic, 600]

=== Debezium について

link:https://access.redhat.com/documentation/ja-jp/red_hat_build_of_debezium[Debezium,window="_blank"] は **Kafka Connect** の仕組みを使用したチェンジデータキャプチャの基盤となる製品です。
データベースに発生した更新イベントをキャプチャして、その更新イベントを **Kafka** のトピックにメッセージとして送信することによって、
その変更内容を **Kafka** に接続している他のシステムに、ニアリアルタイムに連携させることができるようになります。

image::dbsync/dbsync-002.png[pic, 800]

このセクションで作成する内容

* 以下のコンポーネントは既に用意されています
** 同期元、同期先のPostgreSQL
*** postgresql
*** postgresql-replica
** 同期元のPostgreSQLの変更ログをキャプチャするDebezium
* 実装する Camelルート
** DB更新イベントを受信する Kafka Source
** DB更新の内容を抽出
** CREATE/DELETE/UPDATE で処理を分岐して、同期先の PostgreSQL を操作

image::dbsync/dbsync-003.png[pic, 800]

== 2. Debezium からのログを受信する

前章の link:{{ HOSTNAME_SUFFIX }}/workshop/camel-k/lab/postgresql-sink[PostgresSQL との連携,window="_blank"] で 使用したデータベースは、`Debezium` にて変更ログをキャプチャし、イベントに変換して `Kafka` に送信するようになっています。

link:http://kafdrop-{{ USER_ID }}-dev.{{ ROUTE_SUBDOMAIN }}[Kafdrop,window="_blank"] というツールで、Kafka トピックに送信されたメッセージの内容を確認することができます。

こちらのリンクから、link:http://kafdrop-{{ USER_ID }}-dev.{{ ROUTE_SUBDOMAIN }}/topic/debezium.public.products/messages?partition=0&offset=0&count=100&keyFormat=DEFAULT&format=DEFAULT[debezium.public.products,window="_blank"] の内容を確認できます。アクセスして確認してみてください。

image::dbsync/dbsync-004.png[pic,1200]

トピックにはメッセージが4件入っていると思います。
一番下のメッセージが、前章の最後に追加したレコードの内容に対応しています。

[source,json]
----
{
   "schema": {
      "type": "struct",
      "fields": [
         {
            "type": "int32",
            "optional": false,
            "default": 0,
            "field": "id"
         },
         {
            "type": "string",
            "optional": true,
            "field": "name"
         },
         {
            "type": "string",
            "optional": true,
            "field": "__op"
         },
         {
            "type": "string",
            "optional": true,
            "field": "__table"
         },
         {
            "type": "int64",
            "optional": true,
            "field": "__lsn"
         },
         {
            "type": "int64",
            "optional": true,
            "field": "__source_ts_ms"
         },
         {
            "type": "string",
            "optional": true,
            "field": "__deleted"
         }
      ],
      "optional": false,
      "name": "debezium.public.products.Value"
   },
   "payload": {
      "id": 4,
      "name": "melon",
      "__op": "c",
      "__table": "products",
      "__lsn": 23000152,
      "__source_ts_ms": 1682590725891,
      "__deleted": "false"
   }
}
----

`schema` にトピックの中の項目の属性情報があり、`payload` の中に実際の値が格納されています。
項目名の先頭に __ がある項目は、変更イベントのメタデータです。

* __op: イベントが生成される原因となった操作
** c: CREATE 
** r: READ
** u: UPDATE
** d: DELETE
* __table: 変更イベントが発生したテーブル名
* __lsn: Log Sequence Number
* __source_ts_ms: イベントのタイムスタンプ
* __deleted: 削除されたレコードかどうかを識別

それでは、Kafka からメッセージを受信する処理を作成していきます。

OpenShift DevSpaces 左のエクスプローラー上で、右クリックをして、メニューから `New File...` を選択し、`dbsync.yaml` と入力して `Enter` を押してください。
作成したファイルを選択して右クリックし、`Open with Kaoto Graphical Editor for Camel` から Kaoto のグラフィカルエディターを開きます。

まだ Route の定義がないので、新しく Route を作成します。
`+ New` をクリックしてください。

image::file-component/02-file-001.png[pic, 800]

`timer` と `log` が配置された Route が作成されます。

今回は `kafka-source` コンポーネントを使いますので、`timer` と入れ替えます。
`timer` シンボルの メニューをクリックし、`Replace` を選択します。

image::file-component/02-file-002.png[pic, 600]

コンポーネントのカタログが開きます。

`Type: Kamelets` の中から `Kafka Source` を探して選択をしてください。
左上のテキストボックスに `Kafka Sourc` と入力をすると、絞り込みができます。

image::dbsync/dbsync-005.png[pic, 600] 

Route の source として、`kafka-source` コンポーネントが配置されます。
`kafka-source` シンボルをクリックすると、右側にプロパティが表示されますので、確認してください。

Parameters は、以下を入力してください。

* **Topic Names**: debezium.public.products (Debeziumから送信されたDB更新イベントが格納されているKafkaのトピック)
* **Auto Offset Reset**: earliest
** `latest`: 新しいメッセージから受信 （未指定の場合 latest になります）
** `earliest`: 最初のメッセージに遡って受信

image::dbsync/dbsync-006.png[pic, 800] 
image::dbsync/dbsync-007.png[pic, 800]

その他の Parameters(kafka の認証情報) は、`application.properties` に記述しておきます。
OpenShift DevSpaces 左のエクスプローラー上で `application.properties` を開き、以下の設定をコピーして貼り付けてください。

[source, code]
----
# Kafka authentication
camel.kamelet.kafka-source.bootstrapServers=kafka-cluster-kafka-bootstrap.{{ USER_ID }}-dev.svc:9092
camel.kamelet.kafka-source.securityProtocol=PLAINTEXT
camel.kamelet.kafka-source.password=demo
camel.kamelet.kafka-source.user=demo
----

image:dbsync/dbsync-008.png[pic, 1200] 

[TIP]
====
`kafka-source` のシンボルに **!** のマークが表示されているかもしれませんが、必須入力のパラメータを省略しているためです。
今回は `application.properties` から設定を行いますのでそのままでOKです。
====

次に、`log` で出力するメッセージを修正します。
`log` シンボルをクリックすると、右側にプロパティが表示されますので、確認してください。
`Message` に `template message` と入力されていますので、これを `${body}` に変更してください。
これで、ファイルで受信したメッセージの本文をログに出力するようになります。

image::dbsync/dbsync-009.png[pic, 800] 

それでは、実際に動かしてみます。
OpenShift DevSpaces のターミナルで、以下のコマンドを実行してください。

[source, bash]
----
camel run dbsync.yaml --properties=application.properties
----

[TIP]
====
--properties=<propertiesFiles> で、プロパティファイルを指定します。複数ある場合はカンマ(,)で区切ります。
====

ターミナルが開き、作成したインテグレーションが JBang を通して実行されます。 
特にエラーなく実行されたら、ターミナルにKafka受信したメッセージが表示されているはずです。

image::dbsync/dbsync-010.png[pic, 1200] 

Logの確認後、`Ctrl+C` もしくは、ターミナル右上のゴミ箱のアイコンをクリックして、終了してください。

== 3. DB更新イベントを抽出する

Kafkaイベントの中から、`payload` だけを抽出してBodyに格納します。

`log` シンボルのメニューをクリックして、`Preppend` を選択します。

image:dbsync/dbsync-011.png[pic, 600]

コンポーネントのカタログの、`Type: Processor` の中から `Set Body` を探して選択をしてください。
左上のテキストボックスに `Set Body` と入力をすると、絞り込みができます。

image::file-component/02-file-008.png[pic, 600]

これで、`kafka-source` と `log` の間に、`setBody` が追加されました。

`setBody` のシンボルをクリックすると、右側にプロパティが表示されますので、
Expression に、以下の内容を設定してください。

* **Language**: jsonpath
* **Expression**: $.payload

image::dbsync/dbsync-012.png[pic, 600]
image::dbsync/dbsync-013.png[pic, 800] 

それでは、実際に動かしてみます。
OpenShift DevSpaces のターミナルで、以下のコマンドを実行してください。

[source, bash]
----
camel run dbsync.yaml --properties=application.properties
----

ターミナルが開き、作成したインテグレーションが JBang を通して実行されます。 
Set Bodyで payload を抽出した後のメッセージが Log に表示されているはずです。

image::dbsync/dbsync-014.png[pic, 1200] 

Logの確認後、`Ctrl+C` もしくは、ターミナル右上のゴミ箱のアイコンをクリックして、終了してください。

== 4. 同期先のPostgreSQLを更新する

次に、Camel ルートに同期先のPostgreSQLを更新する処理を作成していきます。
まずは、更新イベントが CREATE/DELETE/UPDATE がどうかを判断する `Choice` コンポーネントを配置します。

* link:https://camel.apache.org/components/{{ CAMEL_VERSION }}/eips/choice-eip.html[Choice,window="_blank"]

image::dbsync/ContentBasedRouter.gif[pic, 600] 

=== 4.1 UPDATE処理を作成する

`log` シンボルのメニューをクリックして、`Append` を選択します。

image::dbsync/dbsync-015.png[pic, 600] 

コンポーネントのカタログの、`Type: Processor` の中から `Choice` を探して選択をしてください。
左上のテキストボックスに `Choice` と入力をすると、絞り込みができます。

image::dbsync/dbsync-016.png[pic, 600] 

これで、`log` の後に、`choice` が追加されました。

image::dbsync/dbsync-017.png[pic, 800] 

`choice` の右上の `when` シンボルをクリックすると、右側にプロパティが表示されますので、確認してください。

Parameters は、以下を入力してください。

* **Language**: simple
* **Expression**: ${body['__op']} == 'u'
* **Description**: UPDATE

これは、`Body` メッセージの中に "__op":"u" が含まれている場合（UPDATE処理の場合）に、実行されます。

また、`Description` を変更したことで、`when` シンボルの表示名が `UPDATE` に変更されました。 

image::dbsync/dbsync-018.png[pic, 600]
image::dbsync/dbsync-019.png[pic, 800] 

//image::dbsync/11-dbsync-019.png[width="1200px"]

次に、`Update` の右の `log` シンボルをクリックすると、右側にプロパティが表示されますので、確認してください。

Message は、以下を入力してください。

* **Message**: UPDATE: ${body}


image::dbsync/dbsync-020.png[pic, 800] 

続いて、`log` の下に、`postgresql-sink` を配置します。
`log` シンボルの メニューをクリックし、`Append` を選択します。

image::dbsync/dbsync-021.png[pic, 800] 

コンポーネントのカタログが開きます。
`Type: Kamelets` の中から `PostgreSQL Sink` を探して選択をしてください。
左上のテキストボックスに `PostgreSQL Sink` と入力をすると、絞り込みができます。

image::postgresql/postgresql-008.png[pic, 600]

`postgresql-sink` のシンボルが `log` に続いて配置されます。

`postgresql-sink` シンボルをクリックすると、右側にプロパティが表示されます。

Parameters は、以下のように設定をします。

* *Query*: `UPDATE products SET name=:#name where id=:#id`

image::dbsync/dbsync-022.png[pic, 800]

その他の Parameters(PostgreSQL の認証情報) は、`application.properties` に記述しておきます。
OpenShift DevSpaces 左のエクスプローラー上で `application.properties` を開き、以下の設定をコピーして貼り付けてください。

[source, code]
----
# PostgreSQL authentication
camel.kamelet.postgresql-sink.serverName=postgresql-replica.{{ USER_ID }}-dev.svc.cluster.local
camel.kamelet.postgresql-sink.serverPort=5432
camel.kamelet.postgresql-sink.password=demo
camel.kamelet.postgresql-sink.username=demo
camel.kamelet.postgresql-sink.databaseName=sampledb
----

[TIP]
====
今回は、`同期先` の PostgreSQL にアクセスをしますので、`camel.kamelet.postgresql-sink.serverName` が変更になっていることに注意してください。
====

続いて、`postgresql-sink` に入力するデータをJSON形式に変換するための `marshal` を追加します。
`postgresql-sink` シンボルの メニューをクリックし、`Prepend` を選択します。

image::dbsync/dbsync-023.png[pic, 800]

コンポーネントのカタログが開きますので、`Type: Processor` の中から `Marshal` を探して選択をします。
左上のテキストボックスに `Marshal` と入力をすると、絞り込みができます。

image::data-formats/dataformats-015.png[pic, 600]

`marshal` のシンボルが `log` と `postgresql-sink` の間に配置されます。

Parameters は、以下のように設定をしてください。
他の項目は、デフォルトのままで構いません。

* **Data Format**: json

image::dbsync/dbsync-024.png[pic, 800]

以上で、UPDATE処理の作成は完了です。

=== 4.2 DELETE処理を作成する

`choice` シンボルの メニューをクリックし、`Insert special step` を選択し、カタログから `When` を追加してください。

image::dbsync/dbsync-025.png[pic, 800] 

先ほどのUPDATE処理と同様に、`marshall` と `postgresql-sink` を追加します。
各シンボルの Parameters 項目に、以下の内容を設定してください。

`when`

* **Language**: simple
* **Expression**: `${body['__op']} == 'd'`
* **description**: DELETE

`log`

* **Message**: DELETE: ${body}

`marshal`

* **Data Format**: json

`postgresql-sink`

* **Query**: `DELETE from products where id=:#id`

image::dbsync/dbsync-026.png[pic, 800] 

以上で、DELETE処理の作成は完了です。

=== 4.3 CREATE処理を作成する

`choice` 右下の `otherwise` にCREATE処理を作成します。

UPDATEとDELETEと同様にして、`marshall` と `postgresql-sink` を追加します。
各シンボルの Parameters 項目に、以下の内容を設定してください。

`otherwise`

* **description**: CREATE

`log`

* **Message**: CREATE: ${body}

`marshal`

* **Data Format**: json

`postgresql-sink`

* **Query**: `INSERT INTO products (id, name) VALUES (:#id, :#name)`

最後に、`choice` シンボルの前にある `log` シンボルを削除しておきましょう。

image:dbsync/dbsync-027.png[pic, 800] 

以上で、CREATE処理の作成は完了です。

== 5. Camel/Kafka/Debezium を使ったDBの同期の実行

作成したDB同期の処理を実行してみましょう。
まず、それぞれのDBのテーブルの状態を確認していきます。
下記のコマンドを実行してください。

* 同期元DBの確認: `oc rsh -n {{ USER_ID }}-dev dc/postgresql psql -U demo -d sampledb -c "SELECT * FROM products;"`
* 同期先DBの確認: `oc rsh -n {{ USER_ID }}-dev dc/postgresql-replica psql -U demo -d sampledb -c "SELECT * FROM products;"`

同期元のデータベースのテーブルのレコード数は4、同期先の方はレコード数は0となっているはずです。

image::dbsync/dbsync-028.png[pic,800]

それでは、実際に動かしてみます。
OpenShift DevSpaces のターミナルで、以下のコマンドを実行してください。

[source, bash]
----
camel run dbsync.yaml --properties=application.properties
----

ターミナルが開き、作成したインテグレーションが JBang を通して実行されます。 
Set Bodyで payload を抽出した後のメッセージが Log に表示されているはずです。

image::dbsync/dbsync-029.png[pic, 1200]

別のターミナルを開き、同期先のDBの内容を確認してみてください。

* 同期先DBの確認: `oc rsh -n {{ USER_ID }}-dev dc/postgresql-replica psql -U demo -d sampledb -c "SELECT * FROM products;"`

同期元と同じレコードが追加されています。

//使える
image::dbsync/dbsync-030.png[pic, 800]

同期元DBに対して、CREATE\UPDATE\DELETEの操作をして、同期先DBに反映されることを確認してみてください。

* 同期元DB CREATE: `oc rsh -n {{ USER_ID }}-dev dc/postgresql psql -U demo -d sampledb -c "INSERT INTO products (id, name) VALUES (5, 'strawberry');"`
* 同期元DB DELETE: `oc rsh -n {{ USER_ID }}-dev dc/postgresql psql -U demo -d sampledb -c "DELETE from products where id=2;"`
* 同期元DB UPDATE: `oc rsh -n {{ USER_ID }}-dev dc/postgresql psql -U demo -d sampledb -c "UPDATE products SET name='pineapple' where id=1;"`

実行後、ターミナルにそれぞれの処理が実行されたことを示す Log が表示されます。
